# Plan 02-02: REST Mirror for Non-MCP Clients

## Phase Goal

**As a** developer running AI agents across editors and tools, **I want to** install agent-memory with one command and have it recall my memories by meaning — falling back to keyword search when Ollama is absent, reachable over REST, and able to import my GSD project state, **so that** every agent session starts with the right context, fully locally with no cloud.

This plan delivers the REST slice: scripts, curl, and non-MCP tools can hit the same store (API-01).

<objective>
Add `agent-memory serve-rest --addr 127.0.0.1:7437` — an axum 0.8 HTTP mirror of the four memory operations plus a health endpoint, as thin adapters over the SAME `MemoryService` (and the same WAL SQLite file) the MCP stdio server uses. Separate process by design: editors spawn one stdio process per session; WAL + busy_timeout (Phase 1) make cross-process access safe (RESEARCH Pattern 4 / A3).

Purpose: API-01 — non-MCP integrations get first-class access without a second store or divergent logic.
Output: `rest/` module, `ServeRest` subcommand, loopback-bind guard, green `tests/rest.rs`.
</objective>

## Interface contracts (established by this plan)

- Routes (axum 0.8 `{id}` path syntax, NOT the 0.7 `:id` form): `POST /api/memories` → store (201 + `{"id": N}`), `GET /api/memories?type=&tag=&scope=&limit=` → list (200 + `Vec<MemoryView>` JSON), `POST /api/search` → search (200 + `SearchOutcome`), `DELETE /api/memories/{id}` → forget (200 `{"id":N,"deleted":true}` or 404 `{"id":N,"deleted":false,"reason":"not_found"}`), `GET /health` → 200 `{"status":"ok","embedder":"ready"|"model_missing"|"unreachable"}`.
- `ApiError` in `rest/mod.rs` implementing `IntoResponse`: `BadRequest(String)` → 400, `NotFound` → 404, `Internal(String)` → 500; body is `{"error": "..."}`. Mirrors mcp.rs's two-tier invalid_params/internal_error mapping; `MemoryError::InvalidType` maps to 400.
- `ensure_bind_allowed(addr: &std::net::SocketAddr, allow_remote: bool) -> anyhow::Result<()>` in `rest/mod.rs`: non-loopback + `!allow_remote` → error naming the `--allow-remote` flag; non-loopback + `allow_remote` → Ok (caller logs a warning).
- CLI: `ServeRest { #[arg(long, default_value = "127.0.0.1:7437")] addr: String, #[arg(long)] allow_remote: bool }`.
- The bound address is logged to stderr as an info line containing `REST listening on {local_addr}` — tests parse the port from this line (supports `--addr 127.0.0.1:0`).
