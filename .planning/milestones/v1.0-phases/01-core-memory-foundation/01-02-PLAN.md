<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → server | Untrusted `query` (FTS5 MATCH string), `id` (forget), and filter args cross here |
| server → SQLite (FTS5) | Search reads the corpus; a malformed MATCH string must not crash or inject |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `search`/`forget` SQL | mitigate | FTS5 MATCH query and DELETE are fully parameterized; the `query` is bound as an FTS5 match argument, never concatenated into SQL (Security V5) |
| T-02-02 | DoS | malformed FTS5 query syntax | mitigate | A query that is not valid FTS5 returns a typed `Err` mapped to `McpError::invalid_params` (clean error, no panic); no-match returns `Ok(vec![])` |
| T-02-03 | Information Disclosure | scope filter bypass | accept | Phase-1 `scope` is a soft logical filter (D-03), not an access-control boundary; single local user — no cross-tenant isolation claimed |
| T-02-04 | DoS | unbounded result set | mitigate | `limit` param caps returned rows; a sane default limit is applied when omitted |
| T-02-SC | Tampering | crates.io installs | accept | No new crates beyond Plan 01's pre-audited set; no install-time checkpoint |

No HIGH-severity threat is left unmitigated.
</threat_model>
