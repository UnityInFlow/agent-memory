# Plan 05-01: Redact storage-engine text on every service path; teach the store the format-v1 contract

## Phase Goal

**As a** user, **I want to** export all my memories to a portable file and import them on another machine, **so that** my agent's memory moves with me — across machines, with no cloud sync.

This plan ships the user-approved scope addition first and lays the store contract both Wave-2/3 tracers build on:

- **D-14 (tracer):** today only `search` redacts storage-engine text; `store`, `list` (and therefore `/health`), `update`, `link`/`unlink`, `forget`, `import` and `sweep` still send `sqlite error: …` with table and column names to the client (04-REVIEW IN-01). Import adds another write path through the same mapping, so redaction lands on EVERY public `MemoryService` method before any new path exists — and every later test in this phase asserts redacted text.
- **Store contract (expansion):** `Store::find_by_key` (D-07: a duplicate must map its export key to the *existing* row id), `LinkOutcome::Linked { created }` (D-12: `links_skipped_duplicates` must be countable through the existing `Store::link`), and `ImportedMemory` + `Store::insert_imported` (D-10/D-13: preserved timestamps, always pending). These touch `domain.rs`, `store/mod.rs`, `sqlite.rs` and ripple into `mcp.rs`/`handlers.rs`/`relations.rs` — the same files D-14 touches — so they land here in one wave instead of forcing plans 02 and 03 to each carry partial store edits.

<objective>
1. Generalise `redact_search_error` into `redact_storage_error(op, e)` and apply it to every public `MemoryService` method through the `*_unredacted` inner-fn shape `search` already uses. Prove it in-process for a write path and for `/health` on both transports, mirroring T-04-19.
2. Replace `Store::exists -> bool` with `Store::find_by_key -> Option<i64>` (one caller, one impl) and make `Store::link` report whether it inserted (`LinkOutcome::Linked { created: bool }`, seven sites, not a wire change).
3. Add `ImportedMemory` and `Store::insert_imported`, refactoring the single `memories` INSERT into one private `insert_row` helper so `insert` and `insert_imported` can never drift.

Purpose: clients never see storage-engine text on any surface (the IN-01 deferral is closed), and the import/export tracers in plans 02 and 03 compile against a tested store contract instead of inventing one.
Output: `redact_storage_error` on nine methods with core/REST/MCP proofs; `tests/redaction.rs`; `find_by_key`; `Linked { created }`; `ImportedMemory` + `insert_imported`; README sentence + behavioral change 4.
</objective>

## Interface contracts (established by this plan)

**`redact_storage_error`** (`crates/agent-memory-core/src/service.rs`)

```text
fn redact_storage_error(op: &str, e: MemoryError) -> MemoryError
```
- `InvalidType | InvalidQuery | InvalidArgument` → returned unchanged (client tier).
- `Internal | SchemaTooNew { .. }` → returned unchanged (crate-authored text).
- `Sqlite | Pool | Join | Migration` → `tracing::error!(op, error = %e, "storage error")` then `MemoryError::Internal(format!("{op} failed due to a storage error (details are in the server log)"))`.
- No catch-all arm. `pub const SEARCH_STORAGE_FAILURE` keeps its exact current text; a unit test pins `redact_storage_error("search", <storage variant>)` to `Internal(SEARCH_STORAGE_FAILURE)`.
- Op strings, exactly: `"store"`, `"list"`, `"search"`, `"import"`, `"forget"`, `"link"`, `"unlink"`, `"update"`, `"sweep"`. Plans 02/03 add `"export"` and reuse `"import"`.
- Shape per method: the existing body moves to `async fn <name>_unredacted(...)`; the public `async fn <name>(...)` is `self.<name>_unredacted(..).await.map_err(|e| redact_storage_error("<name>", e))`. A tail `.map_err` on a `?`-laden body is NOT acceptable — early returns would escape unredacted.

**`Store::find_by_key`** (`store/mod.rs`, replaces `exists`)

```text
fn find_by_key(&self, source: Option<&str>, mem_type: MemoryType, content: &str) -> Result<Option<i64>, MemoryError>;
```
SQL: `SELECT id FROM memories WHERE source IS ?1 AND mem_type = ?2 AND content = ?3 LIMIT 1` on the read pool, `.optional()?`. The CR-01 NULL-safety paragraph stays in the doc.

**`LinkOutcome::Linked { created: bool }`** (`domain.rs`)

`created` is `tx.changes() == 1`, read before `commit`. Transports match `LinkOutcome::Linked { .. }` and emit the same JSON as today. Tests assert `created: true` on the first insert and `created: false` on a duplicate or symmetric re-link.

**`ImportedMemory`** (`domain.rs`, beside `NewMemory`) and **`Store::insert_imported`**

```text
pub struct ImportedMemory {
    pub content: String, pub mem_type: MemoryType, pub tags: Vec<String>,
    pub source: Option<String>, pub scope: Option<String>,
    pub created_at: i64, pub access_count: i64, pub expires_at: Option<i64>,
}
fn insert_imported(&self, m: ImportedMemory, now: i64) -> Result<i64, MemoryError>;
```
Row semantics: `created_at`/`access_count`/`expires_at` preserved from the file; `last_accessed = now`; `decay_score = 1.0`; `base_weight` = 2.0 if `mem_type.is_pinned()` else 1.0; `embedding_status = 0` ALWAYS (no embedding parameter exists); `tags` serialised with `serde_json::to_string` like `insert`. Same writer-lock + single-transaction shape as `insert`. The caller owns the import-time `expires_at <= now` skip (D-10); the sweep's own delete predicate is `expires_at < now` — both stated in the trait doc.

**`insert_row`** (private, `sqlite.rs`): one private `struct MemoryRow<'a>` carrying `mem_type, content, tags_json, source, scope, access_count, created_at, last_accessed, expires_at, embedding_status`, and `fn insert_row(tx: &rusqlite::Transaction<'_>, row: &MemoryRow<'_>) -> Result<i64, rusqlite::Error>` holding THE one `memories` INSERT. `insert` calls it with `access_count = 0`, `created_at = last_accessed = now`, `embedding_status = i64::from(embedding.is_some())`; `insert_imported` calls it with the preserved values, `last_accessed = now`, `embedding_status = 0`. Using a struct keeps the helper under clippy's `too_many_arguments` limit.
