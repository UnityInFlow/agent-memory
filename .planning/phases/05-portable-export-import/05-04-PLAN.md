# Plan 05-04: Document the contract and prove it over the real binary

## Phase Goal

**As a** user, **I want to** export all my memories to a portable file and import them on another machine, **so that** my agent's memory moves with me — across machines, with no cloud sync.

Plans 02 and 03 built both halves; this plan makes the contract legible to the user and exercises the shipped binary end-to-end exactly the way a user will.

    1. **Usage** — a bash block with `agent-memory export > memories.jsonl`, `agent-memory export --output memories.jsonl`, and `agent-memory import --from jsonl memories.jsonl`; one sentence: both are CLI subcommands only (no MCP tool, no REST route — a file-path read on an unauthenticated daemon would be an arbitrary-file-read primitive, and the corpus must not cross the JSON-RPC stdout channel) (D-01).
    2. **What travels** — a header line, one record per memory, one record per link; **what does not** — embedding vectors, `decay_score`, `base_weight`, `embedding_status` (derived; recomputed on read or re-embedded locally against the local model pin) (D-04, D-13).
    3. **Format v1** — three tables restating `export.rs` in wire order: header (`record`, `format` = `agent-memory-export`, `version` = 1, `exported_at`, `embedding_model`, `embedding_dim`, `schema_version`, `agent_memory_version`, `exported_rows`, `exported_links`), memory (`record`, `key`, `type`, `content`, `tags`, `source`, `scope`, `created_at`, `last_accessed`, `access_count`, `expires_at`), link (`record`, `from`, `to`, `kind`, `created_at`); notes: `key` is the source row id used only as an export-local key and never becomes an id on import; `relates_to` endpoints appear as stored (smaller id first); links follow all memories; every row is exported — no filters, expired rows included (the importer decides) (D-03, D-05, D-06).
    4. **The reader is strict** — in contrast to the tolerant `gsd-state` importer: any defect (bad header, unknown `record`, unknown field, wrong type, invalid `type`/`kind`, empty content, self-link, a link to a key not in the file, a declared-count mismatch) rejects the whole file with `invalid argument: line N: …` and nothing is written; a file with `version` greater than 1 is refused with `file is format version N but this binary reads up to version 1 — upgrade agent-memory` (D-11).
    5. **Idempotent and safe on a non-empty database** — dedup on the exact `(source, type, content)` key with `source` kept verbatim; re-running the same import is a no-op reported as skipped duplicates; two identical source rows collapse to one; links are remapped through the file's keys, so pre-existing rows never gain edges (D-07, D-08).
    6. **Timestamps** — a table: `created_at` preserved; `expires_at` preserved, and a row already expired at import time (`expires_at <= now`) is skipped and counted, never inserted; `last_accessed` refreshed to import time so restored memories start decay-fresh; `access_count` preserved (provenance only — it does not affect ranking); link `created_at` preserved; a header `exported_at` more than an hour ahead of the local clock prints a warning and continues (D-10).
    7. **Embeddings** — imported rows land pending; the existing lifecycle sweep re-embeds them, 128 per tick, first tick at `serve`/`serve-rest` start; a large restore is keyword-only until the backfill catches up; nothing contacts Ollama during the import itself (D-13).
    8. **The report** — the one-line six counts (`imported`, `skipped duplicates`, `skipped expired`, `links imported`, `links skipped duplicates`, `links dropped` — the last being links whose endpoint was skipped as expired) and the pending-embedding line (D-12).
    9. **`--output` is private and atomic** — created `0600` on Unix as `PATH.export-tmp-<pid>` beside PATH and renamed into place; an existing PATH is replaced; an interrupted export never leaves a partial PATH; Windows permissions follow the directory (Phase 6) (D-02).
    10. **Backup vs export** — for a same-machine, full-fidelity copy (vectors included) stop every agent-memory process and use SQLite's own backup, e.g. `sqlite3 memory.db "VACUUM INTO 'memory-backup.db'"`, or keep the automatic pre-migration backup described under Upgrading; use `export` when the memory must move machines or survive a model change.
    Also: in "Lifecycle: TTL & decay" item 3 append "Rows restored by `agent-memory import --from jsonl` take this path too." In "Run", add `agent-memory export --output memories.jsonl   # portable JSONL export (see Export & import)` beside the existing examples. Keep the "Import from GSD" section as is.
