# Plan 04-07: Gap Closure — Strict update payloads, uniform REST error bodies, race-safe pre-migration backup

## Phase Goal

**As an** agent, **I want to** update existing memories, link related ones, and get hybrid keyword+semantic recall, **so that** my memory **stays current** and connected and I find the right memory even when the phrasing differs.

"Stays current" has two more weak points, and this plan closes both:

- An update that misspells or smuggles a field (`type`, `ttl_sec`) is told it succeeded while part of it was dropped (REVIEW WR-02).
- The very first open after `brew upgrade` (STORE-05) can fail to start, or can leave a "pre-0003" backup that is really a post-migration copy, when an editor's MCP server and the REST daemon start at the same moment (REVIEW WR-01, IN-03).

It also gives the new REST routes the same `{"error"}` body shape as every other client error (IN-02), and documents upgrade and restore for users (IN-01).

<objective>
1. Add `#[serde(deny_unknown_fields)]` to the two merge-patch DTOs only: `mcp::UpdateArgs` and `rest::handlers::UpdateBody`. These are surfaces new in v0.1.0. The [03-01] decision not to add it to the v0.0.1 DTOs stands, so no v0.0.1 behaviour changes.
2. Map axum `Path` and `Query` extractor rejections on the REST handlers to `ApiError` with the JSON body, preserving the extractor's status tier.
3. Make the STORE-05 backup race-safe without new dependencies or migrations:
   - set `busy_timeout` before anything that can contend for the DB;
   - back up to a temp file;
   - verify the copy still carries the probed pre-migration version;
   - rename it into place, and only then prune older same-version backups;
   - treat a `to_latest` failure as success only when a re-probe shows another process already reached `LATEST_SCHEMA_VERSION`.
4. Add a README "Upgrading" section.

Purpose: every client mistake on the update surface is reported, never swallowed, and the only rollback path a v0.0.1 user has (the backup) is always a genuine pre-migration copy.
Output: strict DTOs with end-to-end stdio and REST proofs, uniform rejection bodies, hardened `open()` with deterministic seam tests, and an Upgrading section.
</objective>

## Interface contracts (established by this plan)

**`UpdateArgs` / `UpdateBody`**

- Both are `#[serde(deny_unknown_fields)]`.
- rmcp 1.8 deserializes tool `arguments` straight into `Parameters<UpdateArgs>` via `serde_json::from_value`, and maps a failure to `invalid_params("failed to deserialize parameters: …")`. This was verified in rmcp-1.8.0 `src/handler/server/tool.rs`. MCP `_meta` lives outside `arguments`, so no legitimate key is lost.
- schemars 1.2 emits `"additionalProperties": false` for the type. The 04-02 schema test (`required == ["id"]`, no `default` on any patch field) must stay green.

**REST rejection mapping**

- Handlers take `Result<Path<_>, PathRejection>` / `Result<Query<_>, QueryRejection>`, mirroring the existing `Result<Json<_>, JsonRejection>` pattern.
- A private helper maps a rejection by its status:
  - `rejection.status().is_server_error()` → `ApiError::Internal(rejection.body_text())`;
  - any other status → `ApiError::BadRequest(rejection.body_text())`.

  So a parse failure stays a 400 with the JSON body, and an axum routing misconfiguration stays a 500.

**Pre-migration backup and migration**

`pre_migration_backup(src: &Connection, db_path: &Path, expected_version: i64) -> Result<Option<PathBuf>, MemoryError>`:

1. Temp path: `{db}.backup-tmp-{LATEST:04}-{std::process::id()}`. Deliberately outside the `{db}.backup-pre-{NNNN}-` retention prefix, so no process prunes another's in-flight temp.
2. Copy `src` into the temp file with the Online Backup API, as today.
3. Read `user_version` from the copy.
   - If it differs from `expected_version`, another process migrated in between: remove the temp file (best-effort), log at info, and return `Ok(None)`. Existing backups are never touched.
4. Drop the destination connection.
5. Rename the temp file to `{db}.backup-pre-{LATEST:04}-{YYYYMMDD}`. This is an atomic replace of a same-day stale backup.
6. Remove every OTHER `{db}.backup-pre-{LATEST:04}-*` entry, keeping the final path.
7. Return `Ok(Some(final))`.

Any failure in steps 2, 5 or 6 removes the temp file (best-effort) and ABORTS the open with the existing "pre-migration backup failed (…); refusing to migrate …" `MemoryError::Internal`. At no point is a previous valid backup deleted before a new valid one is in place.

`fn migrate_tolerating_concurrent_upgrade(conn: &mut Connection, migrate: impl FnOnce(&mut Connection) -> Result<(), MemoryError>) -> Result<(), MemoryError>`:

- Run `migrate`.
- On `Err`, re-read `PRAGMA user_version` on the same connection.
  - Equal to `LATEST_SCHEMA_VERSION` → log at info that another process completed the upgrade, and return `Ok(())`.
  - Otherwise → return the original error.

`SqliteStore::open` order:

1. `register_vec_extension`.
2. `Connection::open`.
3. `writer.busy_timeout(5 s)`. This is connection-level, so the file stays byte-untouched for the D-13 refusal.
4. Probe `user_version`, refusing a version that is too new.
5. `prepare_connection`. `apply_pragmas` now sets `busy_timeout` first, before `journal_mode`.
6. If `0 < db_version < LATEST`: `pre_migration_backup(&writer, path, db_version)`.
7. `migrate_tolerating_concurrent_upgrade(&mut writer, …to_latest…)`.
8. The FTS and vec smoke checks and the pool build, unchanged.
