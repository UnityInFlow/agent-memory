## Phase Goal

**As an** agent, **I want to** update existing memories, link related ones, and get hybrid keyword+semantic recall, **so that** my memory stays current and connected and I find the right memory even when the phrasing differs.

This plan delivers the "update existing memories" slice end-to-end (MCP-06): after Task 1 an agent can patch a memory over MCP and old meanings stop matching; after Task 2 the full merge-patch matrix works on both transports including REST PATCH.

<objective>
Ship `memory_update`: JSON-merge-patch semantics with double-Option null handling (D-08), same-transaction FTS re-mirror + vector invalidate/re-embed with outage fallback to the sweep backfill (MCP-06), freshness bump on update (D-09), and a full post-update view response including embedding_status (D-10) — on both MCP and REST.

Purpose: agents can keep memories current instead of forget+re-store (which would destroy ids and, after plan 04-03, relation edges).
Output: `Store::update` + `MemoryService::update` + `memory_update` MCP tool + `PATCH /api/memories/{id}`, locked by tests/update.rs plus transport-level matrix tests.
</objective>
