# Plan 02-05: Gap Closure — Degraded-Mode Filter Fidelity + Bad-Input Error Taxonomy

## Phase Goal

**As a** developer running AI agents across editors and tools, **I want to** install agent-memory with one command and have it recall my memories by meaning — falling back to keyword search when Ollama is absent, reachable over REST, and able to import my GSD project state, **so that** every agent session starts with the right context, fully locally with no cloud.

This plan closes the two verification gaps in that story's fallback slice: the degraded keyword mode must honor the same `tag` filter the semantic mode does (gap 1 / CR-01), and bad search input must return a clean 400/invalid_params on both transports instead of a 500 (gap 2 / WR-05 + WR-04).

<objective>
Close the two gaps recorded in 02-VERIFICATION.md (score 13/15), nothing more:

1. **Gap 1 (SEARCH-03 / review CR-01):** `SqliteStore::search` (the FTS5 keyword fallback) binds only MATCH/mem_type/scope — `args.tag` is never referenced, so a tag-filtered search returns an unfiltered superset exactly when Ollama is down. Add the tag predicate + bind, mirroring `knn_search`'s `?5` predicate, with a dead-embedder regression test.
2. **Gap 2 (API-01 / review WR-05 + WR-04):** a malformed FTS5 MATCH string (e.g. a lone `"`) surfaces as `MemoryError::Sqlite` → `ApiError::Internal` → HTTP 500 in keyword mode, falsifying the "never a 500 for bad input" contract written in rest/mod.rs line 30. Detect FTS5 query-parse errors at the store seam as a new `MemoryError::InvalidQuery` variant mapped to 400 (REST) / invalid_params (MCP), and give mcp.rs the same two-tier client/internal split `map_memory_error` already has (closing WR-04 at the same seam).

Purpose: flip the two partial truths in 02-VERIFICATION.md to verified so Phase 2 passes cleanly.
Output: one bound predicate + one error variant + one shared MCP error mapper, each locked in by regression tests that run with a dead embedder (no Ollama required).
</objective>

## Scope discipline

Only CR-01, WR-05, and WR-04 (which gap 2's `missing:` list names explicitly) are in scope. WR-01/WR-02 (integer clamps), WR-03 (poisoned-mutex taxonomy), WR-06 (meta pin), WR-07 (tag LIKE substring semantics), WR-08, WR-09, and all IN-xx findings are recorded review warnings, NOT verification gaps — do not touch them, even where they sit in the same functions. In particular: keep the existing `LIKE '%' || ? || '%'` substring shape for the new tag predicate (exact-match tag semantics is WR-07's separate concern; the gap is only that keyword mode lacks the predicate the other query paths already have).

## Interface contracts (established by this plan)

- `MemoryError::InvalidQuery(String)` in `crates/agent-memory-core/src/domain.rs` — carries the offending query string; thiserror display message starts with `invalid search query`. It is a CLIENT-input error tier alongside `InvalidType`.
- Error-tier mapping, both transports, after this plan:
  - REST `map_memory_error`: `InvalidType` → 400, `InvalidQuery` → 400, `NotFound` → 404, `Sqlite`/`Pool`/`Join`/`Migration` → 500.
  - MCP `map_mcp_error(e: MemoryError) -> McpError`: `InvalidType` | `InvalidQuery` → `McpError::invalid_params(e.to_string(), None)`; `Sqlite` | `Pool` | `Join` | `Migration` | `NotFound` → `McpError::internal_error(e.to_string(), None)`. (`NotFound` as an *error* is only produced by internal store conditions — MCP's clean not-found is the `Ok(false)` forget result, unchanged.)
- Keyword search SQL (`SqliteStore::search`): WHERE clause gains `AND (?10 IS NULL OR m.tags LIKE '%' || ?10 || '%')`; `args.tag` binds as the 10th `params![]` element (after `limit` at `?9`).
