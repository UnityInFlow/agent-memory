# Plan 02-01: Semantic Search with Graceful Keyword Fallback

## Phase Goal

**As a** developer running AI agents across editors and tools, **I want to** install agent-memory with one command and have it recall my memories by meaning — falling back to keyword search when Ollama is absent, reachable over REST, and able to import my GSD project state, **so that** every agent session starts with the right context, fully locally with no cloud.

This plan delivers the first slice of that story: recall-by-meaning with graceful offline degradation (SEARCH-02, SEARCH-03).

<objective>
Add local Ollama (`nomic-embed-text`) semantic search to the existing memory store: a `vec_memories` sqlite-vec sidecar table, an `Embedder` seam with `OllamaClient` (prod) and `FakeEmbedder` (tests), KNN candidate selection in SQL with a similarity×decay blend in Rust, and automatic degradation to the existing FTS5 keyword path whenever Ollama is unreachable. Every search result carries a `search_mode` indicator. Also creates (does not run) the darwin cross-compile spike workflow that gates the release plan.

Purpose: SEARCH-02 (semantic recall) + SEARCH-03 (graceful fallback) — the core Phase 2 capability. The tool must keep working on a fresh machine with no Ollama.
Output: migration 0002, `embed/` module, extended Store/Service, `search_mode` surfaced over MCP, green `semantic`/`fallback` test suites, spike workflow file.
</objective>

## Interface contracts (established by this plan)

- `Embedder` trait (in `agent_memory_core::embed`): `Send + Sync`, **dyn-compatible**. CRITICAL: native async-fn-in-trait is NOT dyn-safe, and `MemoryService` holds `Arc<dyn Embedder>` (mirroring `Arc<dyn Clock>`). Methods therefore return boxed futures — define `pub type BoxFuture<'a, T> = std::pin::Pin<Box<dyn std::future::Future<Output = T> + Send + 'a>>` and declare `fn embed<'a>(&'a self, inputs: &'a [String]) -> BoxFuture<'a, Result<Vec<Vec<f32>>, EmbedError>>` and `fn health<'a>(&'a self) -> BoxFuture<'a, Result<EmbedderHealth, EmbedError>>`. Implementations use `Box::pin(async move { ... })`.
- `SearchMode` enum (`Semantic` | `Keyword`, serde `rename_all = "lowercase"`) and `SearchOutcome { search_mode: SearchMode, results: Vec<MemoryView> }` (Serialize) in `service.rs` — the ONE shared wire envelope for MCP now and REST in plan 02-02 (RESEARCH Open Question 3).
- `MemoryService::new(store, clock, embedder, decay_cfg)` — embedder is the 4th constructor argument; `MemoryService::search` returns `Result<SearchOutcome, MemoryError>`.
- `Store::insert(&self, new: NewMemory, embedding: Option<Vec<f32>>, now: i64)` — extended signature; `Some` inserts memory + vector + `embedding_status = 1` in ONE writer transaction.
- New Store methods: `knn_search(&self, query: Vec<f32>, args: SearchArgs) -> Result<Vec<(MemoryView, f64)>, MemoryError>` (candidates + cosine distance), `insert_embedding(&self, memory_id: i64, embedding: Vec<f32>)`, `pending_embeddings(&self, limit: usize) -> Result<Vec<(i64, String)>, MemoryError>`.
- CLI: global `--ollama-url` flag with `env = "AGENT_MEMORY_OLLAMA_URL"`, default `http://localhost:11434`.
